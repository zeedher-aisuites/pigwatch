# M0 Known Limitations

M0 is an engineering foundation, not a product increment.

- The API exposes health checks only; there are no telemetry endpoints or domain operations.
- The dashboard is a static engineering-status shell with no data connection.
- PostgreSQL and MQTT are available for local development but no PigWatch component publishes, consumes, or persists telemetry.
- Shared schemas contain provenance vocabulary only; a telemetry envelope is deferred to M1.
- Source contracts define common asynchronous lifecycle only; camera, environment, RFID, and thermal payloads are deferred to their milestones.
- Simulation and vision packages are namespace boundaries without implementations. OpenCV and PyTorch are intentionally absent.
- The Godot directory is a documented placeholder and contains no project.
- Authentication, authorization, production deployment, observability backends, retention, backup, and disaster recovery are not designed in M0.
- Container images and third-party GitHub Actions are pinned by version tags rather than immutable digests; a dependency-pinning policy remains to be defined.
