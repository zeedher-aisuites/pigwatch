# M3 Known Limitations

M3 is a basic local/operator telemetry dashboard, not an analytics, clinical, or production access
surface.

- The dashboard is read-only. It cannot configure sensors, acknowledge events, or control the
  simulator.
- The observation view contains the newest bounded API result (200 rows by default, 500 maximum),
  not cursor-paginated or complete history. Client-side source, measurement, and time filters search
  only that loaded window.
- Refresh uses completion-scheduled HTTP polling rather than streaming. The default interval is ten
  seconds, background tabs skip scheduled requests, and intermediate readings can be persisted
  without appearing in every rendered state.
- Freshness compares the newest loaded `event_time` with the browser clock. The configurable
  60-second default is dashboard policy only, not evidence of sensor, environmental, animal, or
  veterinary condition.
- The historical visualization plots discrete retrieved points only. It provides no interpolation,
  aggregation, thresholds, anomaly analysis, or archive navigation.
- Optimized labels and scalar presentation cover only the three M1 payloads: temperature, relative
  humidity, and ammonia concentration. Supporting new payload contracts requires a deliberate UI
  update.
- Filters are not preserved in the URL or across reloads.
- M3 has no animals, animal state, health interpretation, anomaly detection, predictions, alerts,
  sensor configuration, spatial placement, Digital Farm, Three.js, or other M4+ behavior.
- The local API proxy and loopback Compose configuration do not define production authentication,
  authorization, TLS, multi-tenancy, evidence retention, deployment, backup, or disaster recovery.
